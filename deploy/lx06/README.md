# LX06 端侧语音 Agent —— 让小爱音箱 Pro 自己跑一个语音 Agent

> 一句话：**刷机后，设备自己完成「唤醒 → 识别 → 大模型 → 说话」，不需要家里常开一台后端。**  
> 💡 **普通用户/小白上手**：请直接阅读 **[《小爱音箱 Pro (LX06) 保姆级刷机与大模型部署指南》](./FLASH_GUIDE.md)**（开箱即用，无需配置开发环境）。  
> 🛠️ **开发者与架构规范**：以下文档集为机型底层适配规格与研发日志。原始调研保留在 `docs/reference/`，只作背景，冲突时以本目录为准。

## 1. 目标与非目标

### 目标（Definition of Done）
1. LX06 刷入补丁固件后可 SSH，**原生小爱被旁路**，不再应答语音。
2. 设备上常驻一个 Agent 进程：喊唤醒词 → 识别 → 调**任意 OpenAI 兼容大模型** → 用系统 TTS 播报。
3. 断电重启后**自动恢复**，不依赖任何 PC/NAS。
4. 断网时给出语音提示，不卡死；原生小爱的蓝牙网关等非语音能力不受影响。
5. 全链路可观测：结构化日志 + 一个 `status` 子命令。

### 非目标（本期不做）
- 自定义唤醒词（原生 PNS 即可；见 `docs/00-decision.md` ADR-003）
- AirPlay / 本地音乐 / 多设备 / OTA / 手机 App
- 保留原生小爱语音能力（已明确放弃，见 ADR-004）
- 支持 LX06 以外的机型

## 6. 交给实现 Agent 的方式

把整个 `deploy/lx06/` 目录交给它，第一句话只说：

> 读 `AGENTS.md`，然后按 `README.md` 的"快速开始"执行。P0 未通过前不要写代码。

判断它是否真的读懂，看它是否做到三件事：
1. 先要设备 IP 和刷机授权，而不是直接开始写 Rust；
2. 跑 `scripts/p0-check.sh` 并贴出四条 gate 的原始输出；
3. 根据结果改 README 状态表；只有四条 gate 全过才进入 T2A。

## 7. 关键约束（摘要）

- 只写 `boot0/1`、`system0/1`，**永不写** `bootloader` / `tpl` / `data`。
- 内核与系统镜像必须同版本；每次写入必须读回逐字节校验。
- 刷机前必须只读备份 6 个分区；备份长度必须来自设备真实 `/proc/mtd`，不能沿用 OH2P 的值。
- 镜像读回校验失败立即停止，不改启动参数；若启动参数操作或读回失败，先确认当前槽位状态。
- 设备上不跑本地 ASR / 本地 LLM（A113 算力不够）。

完整纪律见 `AGENTS.md`。
